# Neat SDK Налаштування мережі.

Neat SDK, також відомий як Neat Development Environment, працює всередині контейнера Docker. `sima-cli sdk setup` створює контейнер, готує точку монтування робочого простору хоста, запускає Insight, якщо його активовано, і публікує порти контейнера, які використовуються браузером хоста та DevKit під час розробки.

Цей посібник пояснює найважливіші аспекти мережевої взаємодії під час використання SDK з Modalix DevKit.

## Мережева модель.

Типовий набір SDK містить три компоненти:

- Комп’ютер, на якому розміщено застосунок: на ньому працюють Docker, `sima-cli`, контейнер SDK і ваш веб-переглядач.
- Контейнер SDK: запускає середовище розробки Neat і додаткові служби Insight.
- DevKit: підключається до хост-системи через локальну мережу або пряме з’єднання Ethernet/спільну мережу.

Підтримувана мережа контейнерів SDK — `simasdkbridge`. Не запускайте контейнер SDK безпосередньо з Docker або розширення VS Code Dev Containers, коли вам потрібні мережеві підключення DevKit і Insight. Використовуйте `sima-cli sdk setup`, щоб контейнер, відображення портів, спільний доступ до робочого простору та конфігурація Insight створювалися одночасно.

## Яка конфігурація використовується?

Під час запуску налаштування з інтеграцією DevKit, `sima-cli` виконує наступні дії:

- Мережа Docker: створює або повторно використовує `simasdkbridge`.
- Порти контейнера SDK: публікує. Insight Інтерфейс користувача, відео, RTSP, метадані, WebRTC і веб-порти SSH для підключення до хоста.
- Insight відображення портів: записує згенероване відображення портів до конфігурації робочого простору SDK.
- Налаштування спільного доступу до робочого простору: визначає параметри доступу до робочого простору DevKit з основної системи, коли використовується `--devkit`.
- DevKit Доступ до Інтернету: забезпечує маршрутизацію DevKit через загальне мережеве з’єднання хоста, щоб DevKit міг отримувати доступ до репозиторіїв пакетів і завантажувати необхідні залежності за потреби.
- Linux Маршрутизація в мережі, що використовується спільно: в Ubuntu/Linux для мереж, що використовуються спільно, застосовуються правила перенаправлення/NAT, коли це необхідно.

Використання:

```bash
sima-cli sdk setup --devkit <devkit-ip>
```

## Постійне відновлення спільного мережевого з’єднання в Linux.

На деяких хостах Ubuntu функція спільного використання мережі в NetworkManager може відтворювати ланцюжки брандмауера під час повторного підключення кабелю або перезавантаження хоста. У такому разі налаштування може відновити поточну сесію, але попередить, що відновлення не є постійним.

Для інтерактивного налаштування `sima-cli` запитує підтвердження перед встановленням постійного профілю диспетчера NetworkManager.

Для автоматизації виберіть цю опцію явно:

```bash
sima-cli sdk setup --devkit <devkit-ip> --persistent-network-profile -y
```

Постійний профіль застосовується лише до виявленого спільного мережевого шляху. Він не встановлюється самостійно `-y`.

## DevKit Доступ до Інтернету.

Коли DevKit підключено через рекомендоване мережеве з’єднання Linux/macOS, він використовує основний комп’ютер для доступу до Інтернету. Це важливо, коли DevKit потрібно завантажити пакети, встановити залежності або отримати доступ до зовнішніх служб під час налаштування та розробки.

Якщо команди DevKit не виконуються під час спроби завантажити залежності, перевірте, чи є у основного комп’ютера діючий доступ до Інтернету, і чи активний спільний мережевий шлях. У Linux інструмент діагностики мережі може виявити проблеми з перенаправленням у спільній мережі:

```bash
sima-cli sdk doctor network --devkit <devkit-ip>
```

## Insight та опубліковані порти.

Insight використовує згенеровані порти хоста. Якщо можливо, використовуються значення за замовчуванням, але `sima-cli` може призначити порти, відмінні від стандартних, якщо порт уже використовується.

Щоб переглянути поточне відображення всередині оболонки SDK:

```bash
neat --json
```

Знайдіть `exposedPorts` та запис `insight.webUiUrl`. Використовуйте ці значення під час налаштування потоків DevKit, джерел RTSP, доступу через браузер або вихідних каналів застосунку.
