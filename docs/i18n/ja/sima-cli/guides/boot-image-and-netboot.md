# ブートイメージとネットワークブートの操作

`sima-cli bootimg` でローカルまたはダウンロードしたイメージを準備し、リモートネットワークブートを安全に設定し、アドレス変更から復旧し、書き込み用の eMMC を準備します。

コマンドリファレンス: [`sima-cli bootimg`](../../../../sima-cli/commands/sima-cli-bootimg.md)

## ローカルイメージとキャッシュの再利用

`--images DIRECTORY` を `--netboot` または `--autoflash` と併用すると、ホストにあるアーティファクトからネットワークブートセッションを準備できます。ディレクトリは再帰的に検索されます。eLxr には最小 TFTP アーカイブと、それに一致する復旧用ではない `.img.gz` eMMC イメージがそれぞれ 1 つ必要です。Yocto には TFTP ファイルと `.wic.gz`、`.wic.bmap` イメージを含むリリースアーカイブが 1 つ必要です。セットが曖昧または不完全な場合、TFTP サーバーの起動前に停止します。

元のディレクトリは変更されません。sima-cli は TFTP コンテンツをプラットフォームの一時ディレクトリ内の `sima-cli/netboot` にある管理対象キャッシュへコピーして展開します。元データの識別情報と準備済みファイルのサイズが一致する場合、キャッシュを再利用します。ダウンロードしたネットワークブートイメージも同じキャッシュを使います。`--delete-cache` を追加すると、TFTP サーバーの停止後にそのセッションの管理対象キャッシュだけを削除します。別のセッションが使用中のキャッシュは保持されます。

## 日次ネットワークブートのフォールバック

内部 Modalix eLxr 3.0+ ビルドでは、`--netboot` と `--autoflash` は `-f/--force` が指定され、Artifactory に接続できないか認証が失敗した場合にのみ、公開の日次プラットフォームミラーを使用します。`-f` がなければ準備を停止し、フォールバックを有効にする方法を表示します。サイズと SHA-256 の検証は引き続き必須です。`-v` は正確なビルド名、または `1247`、`3.0`、`develop` などの検索語を受け付け、複数の一致結果を新しい順に表示します。

最小 TFTP アーカイブ、palette `.img.gz` eMMC イメージ、`troot_blob.be` は、選択した同じビルドのものである必要があります。ミラーのアーティファクトが欠落、不一致、または無効な場合、展開や TFTP 起動の前に準備を停止します。ローカルファイル、直接 URL、Yocto、以前の eLxr の経路も引き続き利用できます。

## リモートネットワークブートの準備

`--netboot --devkit 192.168.2.2` で DevKit を選択するか、SDK の検出を使うには `--devkit` を省略します。複数のデバイスがある場合は選択を求められます。見つからなければ TFTP は利用可能なままで、CLI が手動設定の手順を表示します。`--devkit-ip` は引き続き別名として使えます。

デバイスに SSH で接続でき、U-Boot バイナリと環境ファイルが `/boot` にある必要があります。sima-cli は環境形式をブートローダーに合わせ、現在の環境をバックアップし、安全な場合は互換性のない冗長環境形式を変換します。複数インターフェースのホストでも、選択した DevKit へのホスト経路が TFTP サーバーのアドレスを決定します。

デバイスを変更する前に、確認パネルでネットワーク設定、永続的な U-Boot の変更、再起動の影響を表示します。確認の既定値は「いいえ」です。承認すると、必要に応じて `/boot` を一時的に書き込み可能で再マウントし、元のマウントモードを復元し、`/boot/sima-cli-netboot-backup.*` にバックアップを保存し、`boot_targets=net` を設定し、結果を検証して再起動を予約します。準備が失敗した場合は保存した環境を復元し、再起動を防ぎます。

プラットフォーム 2.1.2 以前では、安全に識別できない従来の `fw_env.config` レイアウトを使っている場合があります。その場合、sima-cli はバックアップを復元し、TFTP を動かしたまま、シリアルコンソールで入力する正確な U-Boot コマンドを表示します。

ホストと TFTP サーバーを動かしたままにしてください。設定は変更するまで保持されるため、ネットワークブートに失敗すると再試行や再起動が可能です。既定では SSH を待ち、`netboot>` プロンプトで `f` を入力して書き込みます。`--autoflash` では、選択したデバイスに接続でき、ネットワークイメージで動作していることを確認した後、書き込みを開始します。

```bash
sima-cli -i bootimg -v 1247 --netboot -f --devkit 192.168.2.2
```

## IP アドレス変更からの復旧

Linux の起動時にデバイスのアドレスが変わる場合があります。SSH の確認が古いアドレスを待ち続ける場合は、`netboot>` プロンプトで Ctrl+C を押します。TFTP サーバーは動作し続けます。終了するには `q` を使います。

`d` を入力してマルチキャスト検出を実行します。デバイスが応答しない場合は、別のターミナルで `sima-cli serial` を使ってシリアルコンソールを開き、`ip -4 addr` または `ifconfig` を確認します。正しいデバイスとアドレスが分かったら、`f <ip>` を入力して書き込みます。検出は書き込み対象を自動で選択しません。

## eMMC の書き込み準備

イメージを書き込む前に、sima-cli は LVM ボリュームやバインドマウントを含む、eMMC 上のすべてのマウント済みファイルシステムを列挙します。LVM マッピングを解放する前にアンマウントします。マウントが使用中、実行中のルートファイルシステムや有効なスワップが eMMC を使用中、またはマッピングが有効なままの場合は、書き込みを停止します。それらのファイルシステムを使うプロセスを終了し、ネットワーク復旧環境で再試行してください。アンマウントやイメージ書き込みのエラーが起きた場合、成功とは報告せず書き込みを停止します。
