# 부팅 이미지 및 네트워크 부팅 작업

`sima-cli bootimg`로 로컬 또는 다운로드한 이미지를 준비하고, 원격 네트워크 부팅을 안전하게 구성하고, 주소 변경에 대응하고, 플래싱할 eMMC를 준비합니다.

명령 참조: [`sima-cli bootimg`](../../../../sima-cli/commands/sima-cli-bootimg.md)

## 로컬 이미지 및 캐시 재사용

`--images DIRECTORY`를 `--netboot` 또는 `--autoflash`와 함께 사용하여 호스트에 이미 있는 아티팩트로 네트워크 부팅 세션을 준비합니다. 디렉터리를 재귀적으로 검색합니다. eLxr에는 최소 TFTP 아카이브 하나와 이에 일치하는 복구용이 아닌 `.img.gz` eMMC 이미지 하나가 필요합니다. Yocto에는 TFTP 파일과 `.wic.gz` 및 `.wic.bmap` 이미지를 포함하는 릴리스 아카이브 하나가 필요합니다. 모호하거나 불완전한 세트는 TFTP 서버가 시작되기 전에 중단됩니다.

원본 디렉터리는 변경되지 않습니다. sima-cli는 TFTP 콘텐츠를 플랫폼 임시 디렉터리의 `sima-cli/netboot` 아래 관리 캐시로 복사하고 압축을 풉니다. 원본 식별 정보와 준비된 파일 크기가 계속 일치하면 캐시를 재사용합니다. 다운로드한 네트워크 부팅 이미지도 같은 캐시를 사용합니다. `--delete-cache`를 추가하면 TFTP 서버가 중지된 뒤 해당 세션의 관리 캐시만 삭제합니다. 다른 세션에서 사용 중인 캐시는 보존합니다.

## 일일 네트워크 부팅 대체 경로

내부 Modalix eLxr 3.0+ 빌드에서 `--netboot`와 `--autoflash`는 `-f/--force`가 지정되고 Artifactory에 연결할 수 없거나 인증이 실패할 때만 공개 일일 플랫폼 미러를 사용합니다. `-f`가 없으면 준비를 중단하고 대체 경로를 활성화하는 방법을 안내합니다. 크기 및 SHA-256 검증은 여전히 필수입니다. `-v`는 정확한 빌드 또는 `1247`, `3.0`, `develop` 같은 검색어를 받으며, 여러 결과는 최신 순으로 표시됩니다.

최소 TFTP 아카이브, palette `.img.gz` eMMC 이미지 및 `troot_blob.be`는 모두 선택한 동일 빌드에서 가져와야 합니다. 미러 아티팩트가 없거나 일치하지 않거나 유효하지 않으면 압축 해제 또는 TFTP 시작 전에 준비가 중단됩니다. 로컬 파일, 직접 URL, Yocto 및 이전 eLxr 경로도 계속 사용할 수 있습니다.

## 원격 네트워크 부팅 준비

`--netboot --devkit 192.168.2.2`로 DevKit을 선택하거나, SDK 검색을 사용하려면 `--devkit`을 생략합니다. 장치가 여러 개이면 선택하라는 메시지가 표시됩니다. 장치가 없으면 TFTP를 계속 사용할 수 있고 CLI가 수동 구성 지침을 출력합니다. `--devkit-ip`도 별칭으로 유지됩니다.

장치는 SSH로 접근할 수 있어야 하며 `/boot` 아래에 U-Boot 바이너리와 환경 파일을 제공해야 합니다. sima-cli는 환경 형식을 부트로더와 맞추고 현재 환경을 백업하며, 안전한 경우 호환되지 않는 중복 환경 형식을 변환합니다. 인터페이스가 여러 개인 호스트를 포함하여, 선택한 DevKit으로 가는 호스트 경로가 TFTP 서버 주소를 결정합니다.

장치를 변경하기 전에 확인 패널에 네트워크 설정, 영구 U-Boot 변경 및 재부팅 결과를 표시합니다. 기본 응답은 아니요입니다. 동의하면 필요할 때 `/boot`를 임시로 쓰기 가능하게 다시 마운트하고, 이전 마운트 모드를 복원하고, `/boot/sima-cli-netboot-backup.*`에 백업을 저장하고, `boot_targets=net`을 설정하고, 결과를 검증한 뒤 재부팅을 예약합니다. 준비가 실패하면 저장한 환경을 복원하고 재부팅하지 않습니다.

플랫폼 2.1.2 이하에서는 안전하게 식별할 수 없는 이전 `fw_env.config` 레이아웃을 사용할 수 있습니다. 이 경우 sima-cli는 백업을 복원하고 TFTP를 유지하며 직렬 콘솔에 입력할 정확한 U-Boot 명령을 출력합니다.

호스트와 TFTP 서버를 계속 실행해 두세요. 설정은 변경할 때까지 유지되므로 네트워크 부팅 실패 시 재시도와 재부팅이 가능합니다. 기본적으로 SSH를 기다린 다음 `netboot>` 프롬프트에서 `f`를 입력하여 플래싱합니다. `--autoflash`를 사용하면 선택한 장치에 연결할 수 있고 네트워크 이미지로 실행 중임을 확인한 뒤 플래싱을 시작합니다.

```bash
sima-cli -i bootimg -v 1247 --netboot -f --devkit 192.168.2.2
```

## IP 변경 후 복구

Linux가 부팅될 때 장치에 다른 주소가 할당될 수 있습니다. SSH 검사가 이전 주소를 계속 기다리면 `netboot>` 프롬프트에서 Ctrl+C를 누릅니다. TFTP 서버는 계속 실행됩니다. 종료하려면 `q`를 사용합니다.

`d`를 입력하여 멀티캐스트 검색을 실행합니다. 장치가 응답하지 않으면 다른 터미널에서 `sima-cli serial`로 직렬 콘솔을 열고 `ip -4 addr` 또는 `ifconfig`를 확인합니다. 올바른 장치와 주소를 확인한 다음 `f <ip>`를 입력하여 플래싱합니다. 검색은 플래싱 대상을 자동으로 선택하지 않습니다.

## eMMC 플래싱 준비

이미지를 쓰기 전에 sima-cli는 LVM 볼륨과 바인드 마운트를 포함하여 eMMC 기반의 모든 마운트된 파일시스템을 나열합니다. LVM 매핑을 해제하기 전에 이를 마운트 해제합니다. 마운트가 사용 중이거나, 실행 중인 루트 파일시스템 또는 활성 스왑이 eMMC를 사용하거나, 매핑이 계속 활성 상태이면 플래싱을 중단합니다. 해당 파일시스템을 사용하는 프로세스를 닫고 네트워크 복구 환경에서 다시 시도합니다. 마운트 해제 및 이미지 쓰기 오류는 성공으로 보고하지 않고 플래싱을 중단합니다.
