# Операції оновлення системи

Використовуйте `sima-cli update` для щоденних збірок, підписаних пакетів SWU eLxr 3.0, перевірки A/B, підготовки сховища та обробки постійного накладеного шару.

Довідка команди: [`sima-cli update`](../../../../sima-cli/commands/sima-cli-update.md)

## Внутрішні щоденні оновлення eLxr 3.0+

Внутрішній режим показує попередження про попередній випуск. На пристроях Modalix, які вже працюють під eLxr 3.0+, `sima-cli -i update` спочатку звертається до Artifactory. Відсутні облікові дані, відповіді HTTP 401/403 або 5xx, помилки з’єднання та тайм-аути перемикають на [індекс щоденних образів платформи](https://artifacts.neat.sima.ai/daily-platform-images/index.json). Успішний запит без відповідної збірки не перемикає на резервне джерело.

```bash
sima-cli -i update -f -v 3.0
sima-cli -i update -f -v 3.0.0_daily_develop_B1247
```

Точні збіги мають пріоритет. Часткові запити фільтрують індекс і показують результати від найновішого. Придатні лише збірки з palette SWU. Завантаження з дзеркала перевіряє розмір і SHA-256 з індексу до встановлення підписаного пакета. З `-f` невдале завантаження артефакту з Artifactory може перейти на резервне джерело лише для тієї самої вибраної збірки. Відсутній артефакт або невдала перевірка цілісності зупиняє процес до встановлення.

Пристрої під eLxr 2.1.3 зберігають поведінку оновлення APT і політику `--force`. Для переходу цих пристроїв на 3.0 потрібне відновлення або підготовка системи.

## Підписані оновлення A/B eLxr 3.0

На системі Modalix із підготовленою схемою A/B команда `update` встановлює підписаний повносистемний SWU у неактивний слот, зберігаючи поточний слот і `/data`.

```bash
sima-cli update /path/to/full-system.swu
sima-cli update --ip 192.168.6.5 /path/to/full-system.swu
sima-cli update --inspect
sima-cli update --ip 192.168.6.5 --inspect
```

Для тимчасового розміщення перевіряються `/data`, `/media/nvme/swupdate`, потім `/tmp`; потрібне місце для пакета та запас 64 MiB. SWUpdate також потребує місця для розпакування в `/tmp`. Якщо `/tmp` розміщено в RAM, доступна RAM перевіряється навіть за достатнього місця за даними `df`. Виділену tmpfs можна збільшити лише для поточного монтування, якщо для системи залишиться щонайменше 512 MiB або 10% RAM — більше з цих значень. `--dryrun` повідомляє про можливе розширення без зміни монтування.

NVMe монтується або перемонтовується для читання й запису перед використанням, крім `--dryrun`. Завантажені пакети та тимчасові дані видаляються відразу після успішного встановлення. Невдалі встановлення зберігають підготовлений пакет для діагностики; вихідні файли користувача ніколи не видаляються.

Віддалені оновлення завантажуються на хості, передаються до вибраного сховища плати, перевіряють контрольну суму передачі та запускають SWUpdate на платі. Локальний і віддалений режими перевіряють підписаний пакет і вибирають `update,full`. Якщо `/etc/swupdate/public.pem` відсутній, комплектний сертифікат SiMa тимчасово встановлюється та потім видаляється; наявні ключі зберігаються. `--force` змінює лише перехід на дзеркало й ніколи не вимикає перевірку підпису.

Успішне встановлення потребує перезавантаження. З `--reboot` віддалені оновлення повторно з’єднуються та перевіряють новий слот і підтвердження працездатності. Втрату з’єднання або невдале встановлення слід дослідити до повторної спроби.

## Перевірка A/B

`--inspect` показує обидва слоти, версії та їхню дійсність, поточний слот і слот наступного завантаження, стан очікуваного оновлення та відкату, а також кількість завантажень. Він ніколи не завантажує й не встановлює прошивку, не перемикає слоти, не перезавантажує та не оновлює сам sima-cli.

Для образів із постійним накладеним шаром перевірка читає активну версію з незміненого кореня в `/oldroot` після перевірки його базового пристрою. За потреби інший корінь тимчасово монтується лише для читання з вимкненим відтворенням журналу, після чого відновлюється попередній стан активації LVM. Відсутні або неперевірені метадані залишаються невідомими.

## Обробка налаштувань постійного накладеного шару

Перевірка та звичайні оновлення 3.0 показують огляд накладеного шару лише для читання. Звіт порівнює фактичну базу dpkg із базою нижнього шару та групує записи верхнього шару як конфігурацію/служби, кандидати локального ПЗ, видалення, стан пакетів, кеші/журнали та інші файли. `--verbose` додає повне порівняння пакетів і кількість записів у категоріях.

Коли `simaai-palette-*` вказує на різні ID збірок наборів пакетів, sima-cli попереджає, що постійні метадані походять зі старішого образу, а APT може повідомляти неправильні версії або змішувати файли образу й накладеного шару. Скопійовані до верхнього шару файли не класифікуються автоматично як навмисні налаштування; недоступні або нечитабельні базові дані повідомляються без припущень.

Під час оновлення невідповідність збірок пакетів пропонує процедуру очищення накладеного шару:

1. Перевірте, що вибраний SWU підтримує `SWUPDATE_CLEAN_OVERLAY`.
2. Збережіть перелік і його контрольну суму в `/data/.overlay-backup`.
3. Запустіть SWUpdate з увімкненим очищенням накладеного шару.
4. Виведіть інструкції перевірки після перезавантаження та повторного встановлення.

З `-y` виявлена невідповідність автоматично вибирає очищення. Без `-y` користувач може зберегти накладений шар. Пакет без контракту очищення відхиляється до встановлення чи резервного копіювання. Перелік записує вибір пакетів, ідентичність образу, шляхи, власників і дозволи, але не вміст файлів, базу dpkg, кеші APT чи весь верхній шар. Це інформація для відновлення, а не архів автоматичного відновлення. Та сама процедура доступна через `--ip` на віддаленому DevKit.
