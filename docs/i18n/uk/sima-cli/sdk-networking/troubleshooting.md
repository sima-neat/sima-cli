# Вирішення проблем із мережею SDK.

Використовуйте мережевого лікаря, коли контейнер SDK, Insight інтерфейс користувача, DevKit SSH, RTSP, відео WebRTC або синхронізація робочого простору працюють не так, як очікувалося.

Команда «doctor» призначена лише для перегляду. Вона перевіряє маршрут хоста. Docker статус контейнера, опубліковані порти, Insight інформація про відкриті порти, стан міжмережевого екрана та вибрані параметри. Linux деталі мережевого підключення.

## Проведіть швидку перевірку.

```bash
sima-cli sdk doctor network --devkit <devkit-ip>
```

Якщо існує більше одного контейнера SDK, вкажіть назву контейнера:

```bash
sima-cli sdk doctor network --devkit <devkit-ip> --container <container-name>
```

## Зберіть пакет даних для технічної підтримки.

Коли вам потрібна допомога від служби підтримки SiMa, підготуйте такий набір інформації:

```bash
sima-cli sdk doctor network --devkit <devkit-ip> --collect
```

Щоб обрати місце збереження файлу:

```bash
sima-cli sdk doctor network --devkit <devkit-ip> --collect --output ~/sima-sdk-network-doctor.tar.gz
```

Цей пакет містить очищений образ хоста, Docker, інформацію про маршрутизацію, налаштування брандмауера, NetworkManager і Insight для діагностики відображення портів. Він призначений для підтримки мережевих функцій. Не додавайте вручну ключі SSH, файли облікових даних Docker, файли cookie браузера або інші конфіденційні дані до архіву.

## Найбільш поширені результати.

| Пошук | Значення. | Рекомендована дія. |
| --- | --- | --- |
| `vpn-route` | Шлях до DevKit проходить через VPN або тунельний інтерфейс. | Від’єднайте VPN або налаштуйте маршрутизацію таким чином, щоб DevKit використовував фізичний інтерфейс, призначений для DevKit. |
| `missing-simasdkbridge` | Контейнер SDK запущено, але він не підключено до `simasdkbridge`. | Відтворіть або перезапустіть SDK за допомогою `sima-cli sdk setup`. Уникайте безпосереднього запуску контейнерів розробки VS Code для робочих процесів DevKit. |
| `host-network-mode` | Контейнер SDK було запущено з використанням мережевої конфігурації хост-машини Docker. | Відтворіть SDK за допомогою `sima-cli sdk setup`; мережева взаємодія хоста не підтримується в рамках моделі порту Insight. |
| `port-map-mismatch` | Опубліковані порти Docker не відповідають згенерованій карті портів Insight. | Відтворіть контейнер SDK, щоб `sima-cli` міг повторно згенерувати порти та конфігурацію Insight одночасно. |
| `stale-port-bindings` | Зупинений контейнер SDK зберіг прив’язки портів Docker, які більше недоступні. | Видаліть і створіть контейнер повторно за допомогою `sima-cli sdk setup`. |
| `nm-shared-iptables-blocking` | NetworkManager, який забезпечує спільний доступ до мережі, відхиляє мережевий трафік SDK bridge ще до того, як застосовуються правила Docker. | Запустіть `sima-cli sdk network repair --devkit <devkit-ip>`; додайте `--persist`, якщо потрібно, щоб виправлення зберігалося після повторного підключення/перезавантаження. |
| `container-devkit-reachability` | Контейнер SDK не зміг підтвердити можливість встановлення SSH-з’єднання або перевірити зв’язок із DevKit за допомогою ping. | Перевірте IP-адресу DevKit, шлях кабелю/мережі, SSH-сервіс DevKit та брандмауер хоста. |

## Завантаження необхідних компонентів DevKit завершується невдало.

Коли DevKit використовує рекомендоване з’єднання через спільну мережу, для доступу до Інтернету воно покладається на основний пристрій. Якщо встановлення пакетів, завантаження залежностей або доступ до зовнішніх служб не вдаються на DevKit, перевірте:

- Комп’ютер, на якому розміщено застосунок, має доступ до Інтернету.
- Мережевий інтерфейс хост-машини все ще активний.
- VPN-маршрутизація не визначає потрібний маршрут DevKit.
- Linux правила перенаправлення/NAT все ще діють, якщо NetworkManager відновив спільне з’єднання.

Запустити:

```bash
sima-cli sdk doctor network --devkit <devkit-ip>
```

Якщо лікар повідомляє про проблему, пов’язану з блокуванням спільної мережі NetworkManager, виконайте команду для усунення несправностей, яка відображається у виводі лікаря.

## Відновлення роботи маршрутизації у спільній мережі Linux.

На Ubuntu/Linux на хостах, які використовують спільне мережеве підключення через NetworkManager, виконайте:

```bash
sima-cli sdk network repair --devkit <devkit-ip>
```

Щоб встановити постійний обробник подій після застосування виправлень під час роботи системи:

```bash
sima-cli sdk network repair --devkit <devkit-ip> --persist
```

Ремонт стосується лише мосту SDK і виявленого спільного мережевого шляху, що використовується DevKit. Він не перемикає Docker на мережу хоста і не встановлює глобальну політику `FORWARD` на значення `ACCEPT`.

## Перевірте після ремонту.

Запустіть програму для перевірки ще раз:

```bash
sima-cli sdk doctor network --devkit <devkit-ip>
```

Потім відкрийте URL-адресу Insight, зазначену в звіті:

```bash
neat --json
```

Якщо браузер не може відкрити Insight, перевірте, чи доступний порт хоста `mainUI` з боку браузера хоста, і чи було запущено контейнер SDK за допомогою `sima-cli sdk setup`.
