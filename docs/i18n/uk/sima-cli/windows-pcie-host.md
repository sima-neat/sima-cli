# Установлення Neat PCIe Host у Windows

Установіть випуск хоста Windows PCIe однією командою `sima-cli`. Маніфест
випуску визначає узгоджені MSI-пакети Scheduler і Core, порядок установлення,
версії та контрольні суми. `sima-cli` завантажує й перевіряє весь комплект,
перш ніж передати кожен нативний пакет до Windows Installer.

Ця сторінка описує лише команду `sima-cli`. Щодо передумов, реєстрації карти,
перевірки та відновлення дотримуйтеся сторінки
[Встановлення хоста PCIe](/getting-started/neat-library/pcie-host).

Виконайте команду в PowerShell після встановлення підтримуваного пакета
Platform PCIe, середовища виконання x64 GStreamer MSVC і, якщо ви не використовуєте
`--native-only`, 64-розрядного Python 3.14.
У вікні PowerShell без підвищених прав ви один раз схвалюєте запит адміністратора Windows
для системних MSI-пакетів Scheduler і Core: один крок із підвищеними правами встановлює Scheduler, а потім
Core, і не запускає Core, якщо Scheduler не встановився. Підвищені права отримує лише цей
крок; CLI, кероване середовище
Python і навички користувача залишаються в сеансі та профілі поточного користувача.
Запускайте команду з інтерактивного вікна PowerShell, щоб Windows могла показати запит на
схвалення; вікну, відкритому через «Запуск від імені адміністратора», запит не потрібен.

```powershell
sima-cli neat install core/pciehost/windows/amd64@v<Neat version>
```

Замініть `<Neat version>` на випуск Neat, у якому опубліковано пакети хоста Windows;
це той самий тег випуску, що й у пакетів хоста Ubuntu.

Перед запуском будь-якого MSI `sima-cli` перевіряє інструменти Windows OpenSSH,
запущену службу Platform, GStreamer, сумісні версію й архітектуру Python, pip і теги
wheel (free-threaded-збірка Python не приймає цей wheel).
Якщо передумови не виконано, команда зупиняється без змін нативної інсталяції.
За замовчуванням `sima-cli` створює або повторно використовує
`%USERPROFILE%\pyneatpcie`, установлює туди відповідний wheel `pyneatpcie`
і перевіряє його версію та імпорт. Параметр `--python-executable <path>`
вибирає інше середовище застосунку, а `--native-only` — установлення лише для C++.

Після завершення Windows Installer CLI запускає встановлений засіб діагностики
хоста й синхронізує узгоджену з пакетом навичку `neat-pcie-application-builder`
з каталогами навичок Codex і Claude поточного користувача. Перед запуском будь-якого
MSI CLI також перевіряє, чи цей ідентифікатор навички вільний або вже зареєстрований
для того самого шляху встановленого пакета. Навичка з іншого джерела або
незареєстрований каталог навички з таким самим ідентифікатором залишається без змін,
а встановлення припиняється. Повторне встановлення пакета може замінити лише навичку,
зареєстровану для того самого шляху пакета.

Наостанок, так само як інсталятор Ubuntu запускає `pcie-setup.sh`, CLI запускає
встановлений `pcie-setup.cmd` у тому самому вікні без підвищених прав, також із
`--native-only`. Цей крок налаштовує SSH без пароля до кожної карти й може запитати
пароль карти. Щоб пропустити його, перед командою задайте
`$env:SIMAPCIE_SKIP_SETUP = "1"`; сеанс без інтерактивного введення також пропускає
його, бо перша реєстрація потребує пароля. Пропущений крок виводить команду, яку можна
виконати пізніше. Якщо крок завершується помилкою, встановлені пакети зберігаються,
стан запису стає `setup-failed`, команда завершується з ненульовим кодом і виводить
команду, яка запускає цей крок знову.

Повторний запуск команди виконує ті самі перевірки й у тому самому порядку
відновлює кожен уже встановлений MSI: `sima-cli` передає його до Windows Installer
з `/fa`, що перевстановлює файли пакета. Новіший випуск оновлює пакети на місці й
замінює запис реєстру старішого випуску. Windows Installer не знижує версію
пакета на місці; щоб встановити старіший випуск, видаліть встановлений, як описано
нижче, а потім встановіть старіший. Пакет Python залишається на місці
лише тоді, коли його встановлено з wheel цього випуску і він досі імпортується;
інакше `sima-cli` перевстановлює wheel.
Якщо встановлення нативного пакета або крок pip завершується помилкою,
виправте зазначену проблему; якщо Windows Installer вимагає перезапуску, команда
завершується з кодом `3010`, і потрібно перезапустити Windows. Потім виконайте команду
повторної спроби, яку виводить `sima-cli`: вона вказує точний випуск, визначений під час
цього запуску, тож повторна спроба не вибере інший. Інсталятор повідомляє,
які нативні пакети було успішно встановлено до помилки. Помилка Windows
Installer `1625` означає, що політика контролю застосунків хоста відхилила
пакет. MSI-пакети Neat, а також DLL і модуль розширення Python у першому випуску
не мають цифрового підпису коду. `sima-cli` завантажує їх через HTTPS з каналу
випусків, перевіряє контрольну суму SHA-256 кожного пакета після завантаження й
ще раз перед запуском Windows Installer або pip (у вікні без підвищених прав — і перед
запитом на схвалення, і всередині кроку з підвищеними правами) і зупиняється, якщо пакет
більше їй не відповідає. Корпоративна політика контролю застосунків може блокувати
непідписані двійкові файли; попросіть адміністратора Windows перевірити
політику. `sima-cli` не вимикає жодних засобів захисту Windows. Якщо Windows
Installer не запускається, `sima-cli` повідомляє, який пакет намагався
встановити, надає рекомендації щодо прав доступу та вказує запланований шлях
до журналу інсталятора.

Під час встановлення випуску `sima-cli` записує код продукту кожного MSI до запису
реєстру. Одна команда використовує ці коди, щоб за одного запиту на схвалення
адміністратора в одному кроці з підвищеними правами видалити Core, а потім Scheduler, і
після цього видаляє запис:

```powershell
sima-cli packages list
sima-cli packages remove gh:sima-neat/core/pciehost/windows/amd64 --version INSTALLED_VERSION --yes
```

Замініть `INSTALLED_VERSION` точним значенням із `packages list`. Пакет, якого вже
немає, вважається видаленим. Якщо Windows Installer завершується з помилкою, Scheduler
не видаляється, доки залишається Core, запис зберігається зі станом `remove-failed`, і
ту саму команду можна запустити ще раз. Код виходу `3010` означає, що обидва пакети
видалено, а для завершення потрібно перезапустити Windows.

Команда не видаляє пакет Python поточного користувача, кероване середовище Python або
синхронізовану навичку користувача; вона виводить команди для їх видалення:

```powershell
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" -m pip uninstall -y pyneatpcie
sima-cli playbooks remove neat-pcie-application-builder --yes
```
