# Windows に Neat PCIe Host をインストールする

Windows PCIe ホストのリリースは、1 つの `sima-cli` コマンドでインストールできます。
リリースマニフェストには、対応する Scheduler と Core の MSI パッケージ、
インストール順序、バージョン、チェックサムが記録されています。`sima-cli` は
一式をダウンロードして検証してから、各ネイティブパッケージを Windows Installer に渡します。

このページでは `sima-cli` コマンドのみを説明します。前提条件、カードの登録、検証、
復旧については、[PCIe ホストのインストール](/getting-started/neat-library/pcie-host) の手順に従ってください。

`sima-cli install drivers/windows` でインストールする Platform PCIe パッケージ、x64 GStreamer MSVC ランタイム、および
`--native-only` を使わない場合は 64 ビット版 Python 3.14 をインストールした後、
PowerShell から実行してください。
昇格されていない PowerShell ウィンドウでは、マシン全体にインストールする Scheduler と
Core の MSI パッケージについて、Windows の管理者承認プロンプトを 1 回だけ承認します。1 つの昇格された手順で Scheduler、
続いて Core をインストールし、Scheduler が失敗した場合は Core を開始しません。昇格される
のはこの手順だけです。CLI、管理対象 Python 環境、カスタマースキルは現在のユーザーのセッションとプロファイルに
残ります。Windows が承認プロンプトを表示できるよう、対話型 PowerShell ウィンドウから
コマンドを実行してください。「管理者として実行」で開いたウィンドウではプロンプトは不要です。

```powershell
sima-cli neat install core/pciehost/windows/amd64@v<Neat version>
```

`<Neat version>` は、Windows ホストパッケージを公開している Neat リリースに
置き換えてください。Ubuntu ホストパッケージと同じリリースタグです。

MSI の実行前に、`sima-cli` は Windows OpenSSH ツール、稼働中の Platform サービス、
GStreamer、互換性のある Python のバージョンとアーキテクチャ、pip、wheel タグ
（フリースレッド版 Python は wheel を受け付けません）を確認します。
前提条件を満たさない場合、ネイティブのインストール状態を変更せず停止します。
デフォルトでは `%USERPROFILE%\pyneatpcie` を作成または再利用し、対応する
`pyneatpcie` wheel をインストールして、バージョンとインポートを確認します。
別のアプリケーション環境を使う場合は `--python-executable <path>`、
C++ のみの場合は `--native-only` を指定してください。

Windows Installer の完了後、CLI はインストール済みホスト診断ツールを実行し、
パッケージに対応する `neat-pcie-application-builder` スキルを現在のユーザーの
Codex と Claude のスキルディレクトリに同期します。いずれかの MSI を実行する前に、
CLI は、このスキル ID が未使用であるか、同じインストール済みパッケージのパスに
登録済みであることも確認します。別のソースからのスキル、または同じ ID を持つ
未登録のスキルディレクトリには手を加えず、インストールを中止します。パッケージを
再インストールする場合は、同じパッケージのパスに登録されたスキルだけを置き換えます。

最後に、Ubuntu のインストーラーが `pcie-setup.sh` を実行するのと同様に、CLI は
インストール済みの `pcie-setup.cmd` を同じウィンドウで、そのウィンドウの権限のまま実行します。
`--native-only` の場合も実行します。この手順は各カードへのパスワード不要の SSH を
設定し、カードのパスワードを尋ねることがあります。スキップするには、コマンドの前に
`$env:SIMAPCIE_SKIP_SETUP = "1"` を設定してください。初回の登録にはパスワードが
必要なため、対話型の入力がないセッションでもスキップされます。スキップした場合は、
後で実行するコマンドが表示されます。この手順が失敗した場合、インストール済みの
パッケージはそのまま残り、記録の状態は `setup-failed` になり、コマンドは 0 以外の
終了コードで終了し、この手順を再実行するコマンドが表示されます。

同じコマンドを再実行すると、同じチェックを行い、インストール済みの各 MSI を同じ順序で
修復します。`sima-cli` は各 MSI を `/fomus` 付きで Windows Installer に渡します。これにより、
見つからないファイルとこのリリースより古いファイルを再インストールし、パッケージの
レジストリエントリとショートカットを書き直します。存在していて最新のファイルはそのまま
残ります。置き換えが必要なファイルが使用中の場合、Windows Installer が再起動を求める
ことがあるため、コマンドを再実行する前に実行中の PCIe アプリケーションを終了して
ください。新しいリリースはパッケージをその場でアップグレードし、
古いリリースのレジストリ記録を置き換えます。Windows Installer はパッケージを
その場でダウングレードしません。古いリリースをインストールするには、以下の手順で
インストール済みのリリースを削除してから、古いリリースをインストールしてください。
Python パッケージは、このリリースの wheel から
インストールされ、引き続きインポートできる場合にのみそのまま使用します。それ以外の
場合、`sima-cli` は wheel を再インストールします。
ネイティブパッケージや pip の処理が失敗した場合は、表示された問題を修正してください。
Windows Installer が再起動を要求した場合、コマンドは終了コード `3010` で終了するため、
Windows を再起動してください。その後、`sima-cli` が表示する再試行コマンドを実行して
ください。このコマンドは今回の実行で解決された正確なリリースを指定するため、再試行で
別のリリースが選ばれることはありません。失敗前に完了したネイティブパッケージは報告されます。
Windows Installer のエラー `1625` は、ホストのアプリケーション制御ポリシーが
パッケージを拒否したことを示します。初回リリースの Neat MSI パッケージ、DLL、
Python 拡張モジュールはコード署名されていません。`sima-cli` はこれらをリリース
チャネルから HTTPS でダウンロードし、各パッケージの SHA-256 チェックサムを
ダウンロード後と、Windows Installer または pip を起動する前に再度検証し（昇格されていない
ウィンドウでは、承認プロンプトの前と昇格された手順の中の両方で検証します）、一致しなくなった
パッケージがあれば停止します。企業のアプリケーション制御ポリシーにより、未署名のバイナリーが
ブロックされる場合があります。Windows 管理者にポリシーの確認を依頼してください。
`sima-cli` は Windows のセキュリティ制御を無効にしません。
Windows Installer を起動できない場合、`sima-cli` は対象パッケージ、権限に関する
案内、および予定されていたインストーラーログの保存先を表示します。

`sima-cli` はリリースのインストール時に、各 MSI のプロダクトコードをレジストリの
記録に保存します。1 つのコマンドがそのコードを使い、1 回の管理者承認プロンプトのもと、
1 つの昇格された手順で Core、続いて Scheduler をアンインストールし、その後記録を削除します。

```powershell
sima-cli packages list
sima-cli packages remove gh:sima-neat/core/pciehost/windows/amd64 --version INSTALLED_VERSION --yes
```

`INSTALLED_VERSION` は `packages list` に表示される正確な値に置き換えてください。
すでに存在しないパッケージは削除済みとして扱います。Windows Installer が失敗した場合、
Core が残っている間は Scheduler を削除せず、記録を `remove-failed` 状態で保持するため、
同じコマンドを再実行できます。終了コード `3010` は、両方のパッケージが削除され、
完了するには Windows の再起動が必要であることを示します。

このコマンドは、現在のユーザーの Python パッケージ、管理対象 Python 環境、同期済みの
カスタマースキルを削除しません。これらを削除するコマンドを表示します。

```powershell
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" -m pip uninstall -y pyneatpcie
sima-cli playbooks remove neat-pcie-application-builder --yes
```

`sima-cli` は `%USERPROFILE%\.sima-cli\registry.json` の記録を使ってパッケージを
見つけるため、`sima-cli` またはそのフォルダーを削除する前にパッケージを削除して
ください。記録がなくなった場合は、インストール済みリリースのインストールコマンドを
再実行して記録を復元してから上記のとおりパッケージを削除するか、設定 > アプリ >
インストールされているアプリで `sima-pcie-host`、続いて
`simaai-scheduler-pcie-host` をアンインストールしてください。
`%USERPROFILE%\.sima-cli` フォルダー全体を削除した場合、インストールコマンドは
まず、スキルが sima-cli のレジストリ外にすでに存在するというメッセージで停止します。
メッセージに示されたスキルフォルダーを削除してから、インストールコマンドを再実行
してください。

記録はインストールを実行した Windows アカウントに属し、パッケージはコンピューター
全体にインストールされます。別のアカウントは同じインストールコマンドを実行して、
自身の記録、Python 環境、スキル、カードの SSH キーを取得します。この場合、パッケージは
再インストールされず修復されます。`sima-cli packages remove` は、パッケージを
アンインストールする前に、昇格したステップで他のアカウントの記録を読み取ります。
他のアカウントの記録に含まれるパッケージ、またはその記録を読み取れないため含まれて
いる可能性があるパッケージはすべて残し、該当するアカウントを表示して、現在の
アカウントの記録だけを削除します。最後に記録を削除したアカウントがパッケージを
アンインストールします。
