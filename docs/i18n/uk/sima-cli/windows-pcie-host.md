# Установлення Neat PCIe Host у Windows

Установіть випуск хоста Windows PCIe однією командою `sima-cli`. Маніфест
випуску визначає узгоджені MSI-пакети Scheduler і Core, порядок установлення,
версії та контрольні суми. `sima-cli` завантажує й перевіряє весь комплект,
перш ніж передати кожен нативний пакет до Windows Installer.

Виконайте команду в PowerShell після встановлення підтримуваного пакета
Platform PCIe та середовища виконання x64 GStreamer MSVC. Пакет Platform
відповідає за підписаний драйвер, бібліотеки хоста й службу `SiMaMlaDaemon`;
Neat не замінює та не оновлює їх.
Windows може запросити схвалення адміністратора для системних MSI-пакетів Scheduler і
Core. Підвищені права отримують лише ці нативні інсталятори; CLI, кероване середовище
Python і навички користувача залишаються в сеансі та профілі поточного користувача.
Звичайний користувач має запускати команду з інтерактивного вікна PowerShell, щоб Windows
могла показати запит на схвалення.

```powershell
sima-cli neat install core/pciehost/windows/amd64@3.0
```

Перед запуском будь-якого MSI `sima-cli` перевіряє інструменти Windows OpenSSH,
запущену службу Platform, GStreamer, сумісні версію й архітектуру Python та pip.
Якщо передумови не виконано, команда зупиняється без змін нативної інсталяції.
За замовчуванням `sima-cli` створює або повторно використовує
`%USERPROFILE%\pyneatpcie`, установлює туди відповідний wheel `pyneatpcie`
і перевіряє його версію та імпорт. Параметр `--python-executable <path>`
вибирає інше середовище застосунку, а `--native-only` — установлення лише для C++.

Після завершення Windows Installer CLI запускає встановлений засіб діагностики
хоста й синхронізує узгоджену з пакетом навичку `neat-pcie-application-builder`
з каталогами навичок Codex і Claude поточного користувача. Під час першого
встановлення налаштуйте SSH-доступ до карти без пароля:

```powershell
& "C:\Program Files\SimaPCIeHost\bin\pcie-setup.cmd"
```

Команда знаходить адреси карт через локальні з'єднання керування `10.0.N.1`.
Якщо автоматичне виявлення недоступне, використайте `-Hosts 10.0.0.2`.
OpenSSH запитує пароль карти лише тоді, коли відкритий ключ ще не зареєстровано;
команда не зберігає пароль. Обгортка застосовує `ExecutionPolicy Bypass` лише
до процесу цього встановленого сценарію, щоб непідписаний засіб першого випуску
працював зі стандартною локальною політикою Windows PowerShell. Вона не змінює
політику виконання користувача чи комп'ютера; політика, примусово задана
адміністратором, має пріоритет.

Повторний запуск команди відновлює або оновлює комплект нативних пакетів.
Відповідний працездатний пакет Python перевіряється й залишається на місці.
Якщо встановлення нативного пакета або крок pip завершується помилкою,
виправте зазначену проблему й повторіть команду. Інсталятор повідомляє,
які нативні пакети було успішно встановлено до помилки. Помилка Windows
Installer `1625` означає, що політика контролю застосунків хоста відхилила
пакет. Використайте схвалений підписаний випуск або попросіть адміністратора
Windows перевірити політику; не вимикайте засоби захисту Windows. Якщо Windows
Installer не запускається, `sima-cli` повідомляє, який пакет намагався
встановити, надає рекомендації щодо прав доступу та вказує запланований шлях
до журналу інсталятора.

Видаліть Scheduler і Core через «Установлені програми» Windows або `msiexec`.
Пакет Python видаляється з керованого середовища окремо:

```powershell
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" -m pip uninstall pyneatpcie
```
